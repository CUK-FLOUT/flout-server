# FCM 토큰 등록·갱신

`PUT /api/notifications/tokens`

로그인한 주민·운영자 모두 사용할 수 있습니다. `Authorization: Bearer {accessToken}`이 필요하며 사용자 ID는 JWT에서 가져옵니다.
Swagger 태그는 `알림`입니다. 경로·쿼리 파라미터는 없습니다.

## 요청

```json
{
  "token": "example-fcm-token",
  "previousToken": "previous-example-fcm-token"
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| token | O | 클라이언트에서 받은 FCM 토큰. 공백·제어문자 없는 ASCII 문자열, 최대 2048자 |
| previousToken | X | 교체할 이전 토큰. 1~2048자, token과 같은 문자 규칙. 생략 또는 null 허용 |

- 최초 등록·로그인 시 `token`만 보냅니다. 여러 기기는 각각 등록할 수 있습니다.
- 같은 토큰을 재등록하면 기존 ID를 유지하며 사용자 연결과 갱신 시각을 갱신합니다.
- 같은 기기에서 계정이 바뀌면 해당 토큰은 현재 로그인 사용자에게만 연결됩니다.
- 토큰이 바뀌면 `previousToken`도 보내 이전 토큰을 교체합니다. 본인 소유의 이전 토큰만 삭제되며, 다른 사용자의 토큰은 삭제하지 않습니다.
- 이전 토큰이 없거나 새 토큰과 같아도 성공합니다. 새로운 토큰 등록과 이전 토큰 교체는 한 트랜잭션에서 처리합니다.
- 토큰 원문은 응답에 포함하지 않습니다. SHA-256 해시의 유일 제약과 DB upsert로 중복 등록을 방지합니다.
- 현재 API는 토큰을 저장하며 Firebase에 실제 토큰의 유효성을 확인하거나 푸시를 발송하지 않습니다.

## 응답

```json
{
  "isSuccess": true,
  "status": 200,
  "code": "NOTIFICATION_200_1",
  "message": "FCM 토큰을 등록·갱신했습니다.",
  "result": { "tokenId": 1 },
  "timeStamp": "2026-11-02 10:00:00"
}
```

| 상태 | 코드 | 조건 |
| --- | --- | --- |
| 400 | COMMON_400_2 | 토큰 누락·빈 문자열·길이 초과·허용하지 않는 문자·본문 형식 오류 |
| 401 | COMMON_401_1 | 인증 누락 또는 현재 사용자가 DB에 없음 |
| 401 | COMMON_401_3 | 만료되거나 유효하지 않은 JWT |
| 406 | COMMON_406_1 | 지원하지 않는 응답 형식 |
| 415 | COMMON_415_1 | 지원하지 않는 요청 본문 형식 |

공통 발송 기능은 [FCM 발송 문서](fcm-delivery.md)를 참고합니다. 토큰 삭제 API와 개별 업무 이벤트 연결은 포함하지 않습니다.
