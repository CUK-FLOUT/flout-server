# 우선점검 선정 순서 저장

`PUT /api/admin/priority-inspections/order`

Swagger 그룹: `운영자-우선점검 관리`

운영자 토큰과 `Content-Type: application/json`으로 요청합니다.

## 요청

```json
{
  "applicationIds": [3, 1, 2]
}
```

`applicationIds`는 원하는 순서대로 나열한 현장점검 신청 ID 목록입니다.
점검 ID가 아니며 null·빈 목록·null 항목·0 이하 ID·중복 ID는 허용하지 않습니다.
현재는 부천시 관할 운영자가 부천시 주소의 신청만 처리합니다.

필터 및 페이지 밖의 신청을 포함해 관할 지역의 우선점검 대상 전체 ID를 전달해야 합니다.
일부 ID만 보내면 409로 거절하며 누락된 신청을 임의로 삭제하거나 재정렬하지 않습니다.
오류 메시지: `관할 지역의 우선점검 대상 전체 신청 ID를 applicationIds에 포함해주세요. 필터와 페이지 밖의 신청도 모두 포함해야 합니다. 지정·취소로 목록이 변경된 경우 다시 조회한 후 요청해주세요.`
조회 이후 신규 지정·취소가 있었다면 전체 목록을 다시 조회한 뒤 요청합니다.
동시에 순서만 바꾼 경우 마지막으로 처리된 요청의 전체 순서를 저장합니다.

## 처리

- 목록의 첫 번째 신청부터 1순위로 저장합니다.
- 변경한 신청마다 순서 변경 운영자와 한국 시간 기준 변경 시각을 기록합니다.
- 동일 순서로 재요청하면 순서 변경 운영자·시각을 갱신하지 않습니다.
- 관할 행 잠금으로 지정·취소·순서 저장을 순차 처리합니다.
- 실패하면 모든 순위 및 순서 변경 정보가 롤백됩니다.
- 신청·내부 메모·점검 상태·담당자·방문 일정·처리 이력은 유지합니다.
- 최초 지정 운영자와 지정 시각은 유지합니다.
- 신규 지정 및 취소 후 재지정은 마지막 순위로 추가합니다.
- 지정 취소는 남은 신청의 상대 순서를 유지하면서 순위를 1부터 정리합니다.
- 이 API는 순서 저장만 처리하며 목록 조회 API는 추가하지 않습니다.

## 200 응답

```json
{
  "isSuccess": true,
  "status": 200,
  "code": "PRIORITY_INSPECTION_200_3",
  "message": "우선점검 선정 순서가 저장되었습니다.",
  "result": {
    "applications": [
      {"applicationId": 3, "receiptNo": "000003", "selectionOrder": 1},
      {"applicationId": 1, "receiptNo": "000001", "selectionOrder": 2},
      {"applicationId": 2, "receiptNo": "000002", "selectionOrder": 3}
    ]
  },
  "timeStamp": "2026-10-29 10:00:00"
}
```

`receiptNo`는 신청 ID를 최소 6자리 숫자 문자열로 표시한 값입니다.
신청 생성·점검 상태 변경·배정·우선점검 지정 응답과 동일한 표시 규칙이며 DB의 기존 `IA-` 접수번호와 구분합니다.
조회 API를 연동할 때는 저장된 `selection_order` 오름차순으로 정렬해야 합니다.

## 오류

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | COMMON_400_2 | 목록 누락·빈 목록·null·잘못된 신청 ID·요청 본문 오류 |
| 400 | PRIORITY_INSPECTION_400_1 | 신청 ID 중복 |
| 401 | COMMON_401_1 / COMMON_401_3 | 인증 누락·유효하지 않은 토큰 |
| 403 | COMMON_403_1 | 운영자 권한 없음 |
| 403 | PRIORITY_INSPECTION_403_1 | 관할 접근 권한 없음 |
| 404 | APPLICATION_404_2 | 신청 없음 |
| 409 | PRIORITY_INSPECTION_409_1 | 우선점검 미지정 신청 포함 |
| 409 | PRIORITY_INSPECTION_409_2 | 전체 대상 목록 누락 또는 지정 목록 변경 |
| 406 | COMMON_406_1 | 지원하지 않는 응답 형식 |
| 415 | COMMON_415_1 | 지원하지 않는 요청 본문 형식 |

요청 형식 오류·빈 목록·null·0 이하 ID는 400입니다.
유효한 ID 목록을 보냈지만 현재 지정된 전체 목록과 일치하지 않으면 409입니다.
이슈 #39의 완료 조건에도 이 구분을 동일하게 반영해야 합니다.

## DB

V20은 지정 테이블에 `selection_order`, `order_updated_by_user_id`, `order_updated_at`을 추가합니다.
기존 지정은 지정 시각·신청 ID 순서로 순위를 부여하고 최초 지정 정보는 유지합니다.
보정용 테이블은 마이그레이션 안에서 생성하고 삭제합니다.
