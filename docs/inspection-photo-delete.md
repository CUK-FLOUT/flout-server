# 현장점검 초안 사진 삭제

DELETE `/api/admin/inspections/{inspectionId}/attachments/{photoId}`

부천시 관할 ADMIN이 현장점검 결과의 DRAFT 사진 한 장을 삭제합니다. photoId는 사진 업로드 또는 결과 조회 응답의 `photos[].photoId`입니다. 주민 신청 사진의 attachmentId와 구분합니다. 요청 본문과 쿼리 파라미터는 없습니다.

마지막 초안 사진도 삭제할 수 있습니다. 이후 결과 공개 시에는 기존 검증에 따라 사진 최소 1장이 필요합니다. 공개된 사진은 삭제할 수 없고, 초안 내용·취약지점·권장조치·주민 신청 첨부자료·점검/신청 상태 및 이력은 유지합니다. 초안의 수정 시각은 갱신합니다.

200 `INSPECTION_200_6`: `현장점검 사진이 삭제되었습니다.`

```json
{
  "isSuccess": true,
  "status": 200,
  "code": "INSPECTION_200_6",
  "message": "현장점검 사진이 삭제되었습니다.",
  "result": {
    "inspectionId": 19,
    "photoId": 1
  },
  "timeStamp": "2026-11-05 14:00:00"
}
```

응답 헤더는 `Cache-Control: no-store`입니다. 삭제 성공 후 프론트는 해당 photoId를 목록에서 제거하거나 결과를 다시 조회합니다.

- 400 `COMMON_400_3`: 점검·사진 ID가 양의 Long이 아님.
- 401 `COMMON_401_1` / `COMMON_401_3`: 미인증 / 만료·유효하지 않은 토큰.
- 403 `COMMON_403_1`: 운영자 권한 없음.
- 403 `INSPECTION_403_1`: 운영자 또는 점검이 부천시 관할이 아님.
- 404 `INSPECTION_404_1`: 점검을 찾을 수 없습니다.
- 404 `INSPECTION_404_2`: 현장점검 사진을 찾을 수 없습니다. 다른 점검 사진과 이미 삭제한 사진도 동일 응답입니다.
- 409 `INSPECTION_409_5`: 공개된 현장점검 사진은 삭제할 수 없습니다.
- 500 `COMMON_500_1`: DB 처리 실패. 사진 삭제와 저장소 정리 요청을 함께 롤백합니다.

삭제는 업로드·임시저장·공개와 동일한 점검 잠금으로 직렬화하며 잠금을 획득한 뒤 사진 소속과 DRAFT 상태를 확인합니다. 삭제가 먼저 완료되어 사진이 0장이 되면 공개는 거절하고, 공개가 먼저 완료되면 삭제는 거절합니다.

사진 메타데이터 삭제와 객체 정리 요청은 같은 DB 트랜잭션으로 커밋합니다. 커밋한 뒤 저장소 객체를 삭제하며 저장소 정리에 실패해도 DB 삭제는 성공으로 반환하고 기존 정리 작업으로 재시도합니다. 정리가 완료되기 전까지 이미 발급한 파일 URL은 유효할 수 있습니다. DB 변경·새 테이블은 필요하지 않습니다.
